# SAP → Provisor: ручное сопоставление

Техническая страница доступна только пользователям с ролью `admin`. Очередь использует отдельные таблицы `sap_matching_source_batches` и `sap_matching_source_items`. Она не читает активные складские снимки и не изменяет `stock_snapshots`, `branch_stock` или `reference_update_statuses`.

## Первичная загрузка

Предпочтительный источник — сохранённые проверенные GetBalance JSON по plant 1001–1011 и 1013, LGORT 1000. Администратор загружает каждый файл в `POST /api/admin/sap-provisor/source/import`, задавая общий `sourceVersion`. Повторная загрузка того же version/plant/hash идемпотентна; другой файл под тем же идентификатором отклоняется.

Архивные файлы также поддерживаются:

- `sap_all_unique_20261023.json` восстанавливает полную техническую совокупность из 5 266 SKU, но не содержит plant и SAP-наименований; импортируется с пустым plant как `historical_sku_list`.
- `sap_unmapped_20261023.csv` восстанавливает 1 134 строки проверки с именами и производителями, но это уже отфильтрованная, а не полная совокупность.

Числа 5 266 и 1 134 не зашиты в код. Идентичность определяется консервативно по нормализованному `Product.code`; отсутствующие и неоднозначные товары сохраняются в диагностике, но не попадают в очередь подтверждения.

`POST /api/admin/sap-provisor/source/refresh` является отдельной явной администраторской операцией. Она вызывает существующий GetBalance-клиент только по запросу администратора и сохраняет результат исключительно в matching-source таблицы. Открытие страницы SAP не вызывает SAP.

## Развёртывание

1. Сделать штатную резервную копию PostgreSQL.
2. Применить `backend/scripts/migrations/20261025_sap_matching_source.up.sql`.
3. Развернуть backend и frontend из одного коммита.
4. Загрузить и проверить исторический источник через admin endpoint. Не использовать stock-import endpoint.
5. Проверить число уникальных, resolved, missing и ambiguous SKU, затем открыть очередь.

Подтверждение повторно проверяет Goods ID через официальный Goods API Provisor. Оно использует существующие `competitor_code_mappings` и `products.provisor_goods_id`; автоматического сопоставления нет.

## Откат

1. Откатить приложение штатным релизным процессом.
2. Если matching-source данные больше не нужны, после резервной копии и отдельного одобрения выполнить `20261025_sap_matching_source.down.sql`.
3. Down-миграция удаляет только технический источник; складские данные и подтверждённые Provisor-сопоставления она не затрагивает.
